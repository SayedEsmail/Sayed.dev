PROJECT CASE STUDY 01

Routz Fleet System

Role: Frontend Developer / Vue.js Engineer

Enterprise Fleet Tracking

The Problem:

Fleet dispatch operators struggled with fragmented legacy tools that lacked real-time sync. Rendering hundreds of active passenger vehicles moving continuously snapped browser performance, causing severe dispatch script freezes and map markers lag. The tool also required support for schools and corporate routes under custom organization routing permissions.

Architectural Blueprint:

Consolidated three separate customer experiences (Super Admin management, B2B Operator dashboards, and Passenger subdomain routes) into a single Vue 3 SPA codebase. Implemented layout injection engines driven dynamically by domain hostname resolution.

Key Engineering Decisions:

Why WebSocket Viewport Culling? Rather than rendering all global vehicles, coordinate streams check the operator bounds, rendering and caching only visible markers to cut map DOM nodes.
Why Pinia Store Separation? Isolated fleet stores from user auth properties, creating modular, lightweight state slices that avoid complex Vuex action dispatchers.

Tangible Business & Product Impact:

  • ~35% faster workflow: Fleet dispatchers experienced seamless real-time coordinate renders without script delays.
  • ~50% acceleration: Domain-driven layouts automated B2B customer subdomain onboarding speeds.
  • ~25% lower queries: Cached vehicle offline buffer arrays eliminated redundant WebSocket reload hits.
PROJECT CASE STUDY 02

Untap SaaS Platform

Role: Senior Frontend Software Engineer (Vue.js)

Multi-Tenant SaaS

The Problem:

Corporate B2B clients running dynamic innovation programs needed a visual, white-labeled solution letting them customize templates, logos, and layouts directly. Building custom form builders and page editors led to high development overhead, while nested payment cart operations scaled exponentially (O(N*M)) on large collective invoices, dragging down checkout rates.

Architectural Blueprint:

Unified three standalone SPAs (Super Admin panel, client program designer, and public participant subdomains) inside a 3-in-1 single Vue 3 codebase. Designed a runtime white-labeling theme manager that injects fetched client colors and layouts config directly into the DOM as root CSS custom properties.

          ▼                 ▼                 ▼
    [SurveyJS Form]  [GrapesJS Studio]  [Payment Cart]

Key Engineering Decisions:

Why SurveyJS + GrapesJS Overrides? Integrated third-party builders to avoid re-writing core form engines, applying dynamic MutationObserver patches to bypass GrapesJS upload limits safely.
Why O(N) Cart Refactoring? Redesigned complex cart payment calculations from nested exponential loops down to single-pass maps, optimizing browser execution under heavy loads.

Tangible Business & Product Impact:

  • ~60% support decrease: Custom visual builder patches allowed clients to self-manage layouts, eliminating tickets.
  • ~15% checkout conversions boost: Speeding calculation bounds from O(N*M) to O(N) removed purchase lagging.
  • ~45% faster rollout: Shared state stores and standardized layouts cut feature development time in half.
PROJECT CASE STUDY 03

Zads Education Marketplace

Role: Full-Stack & Systems Developer

Monorepo & Framework Migration

The Problem:

A tutoring marketplace platform connecting parents with local tutors in Egypt lacked a unified geography database, causing high user bounce rates. In addition, tutors needed flexible multi-modal pricing tables (at student's home, group classes, online, offline) which required complex database join logic and type-safety.

Architectural Blueprint:

Designed a full-stack monorepo bridging 4 distinct projects: zads_web (Nuxt 3 SSR), zads-api (Express API), zads-dashboard (Vue 3 admin), and zads-app (Next.js 16 + Zustand + React 19 targeted progressive migration).

Key Engineering Decisions:

Why Haversine Geo-proximity Search? Engineered a multi-level ranking algorithm based on Haversine distance, matching tutors by localized nested region stages (Area → City → Governorate).
Why Progressive React Migration? Consolidated legacy Nuxt and Vue web portals into a single Next.js 16/React 19 build step-by-step, preserving stable REST Express endpoints to prevent platform downtime.

Tangible Business & Product Impact:

  • ~20% lower bounces: Parents matched with nearby localized tutors instantly, reducing exit rates.
  • ~30% active listings expansion: The flexible 5-point pricing matrix let tutors set specific values, increasing signup.
  • ~90% redirect reduction: Cookie-persisted CASL authorization resolved server-side rendering auth mismatch loops.
